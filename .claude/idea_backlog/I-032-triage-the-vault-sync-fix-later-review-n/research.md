### task-3-review-go.md (subagent a-a917a738)

2. `pkg/vaultsync/repo.go:156` with `:183` - "a command that had already ended well keeps its result" has a small race. In Go 1.22 `Cmd.Wait` replaces a nil error with the watcher's error (`exec.go:910-911`). If the cancel lands after git exited 0 but before `Wait` reads the watcher result, `Cancel` either succeeds on the not-yet-reaped group (error = `context.Canceled`) or gets `ESRCH`, which is not `os.ErrProcessDone` and is wrapped. Fix if wanted: in `Cancel`, return `os.ErrProcessDone` when `Kill` returns `syscall.ESRCH`, and in `run` prefer `cmd.ProcessState.Success()` over the wrapped error.
